# Contributing to Awesome Sports Analytics

Thank you for taking the time to contribute. The goal of this list is to remain genuinely useful to practitioners — data analysts, sports scientists, coaches, and developers who need reliable, vetted resources.

## What We're Looking For

Good additions are:

- **Publicly accessible** — free-to-access, open-source, or with a meaningful free tier
- **Practically useful** — tools, datasets, formulas, or articles that help someone build something or make a better decision
- **Evergreen** — stable resources that won't be dead links in 6 months
- **Specific** — a focused tool or dataset, not a homepage with nothing on it

We accept resources across all categories in the list: sports performance, betting models, nutrition science, cycling, pet health, and related data infrastructure.

## What We Don't Accept

- Paywalled content without a clear free preview or abstract
- Landing pages with no actual resource content
- Duplicate links (check first)
- Tools with no meaningful user base or documentation
- Anything that is primarily a sales page

## How to Submit

1. Fork this repository
2. Add your resource to the appropriate section in `README.md`
3. Follow the existing table format:

```markdown
| [Resource Name](https://example.com/page) | Type | Clear one-sentence description of what it does and why it's useful. |
```

4. If your resource doesn't fit an existing category, suggest a new one in your PR description
5. Open a pull request with a brief explanation of what you're adding and why

## Format Guidelines

- **Link text**: Use the actual resource name, not a keyword phrase
- **Description**: One sentence max. What does it do? Who is it for? What makes it worth including?
- **Type column**: One of — `Dataset`, `Python Lib`, `R Package`, `Tool`, `Article`, `Paper`, `Book`, `Calculator`, `API`, `Platform`, `Video Series`
- **No affiliate links**
- **No tracking parameters in URLs**

## Formulas & Code Blocks

If you're adding a formula or code snippet to an existing section, keep it clean and self-contained. Show the variables. Use fenced code blocks (` ``` `).

## Self-Promotion

It's fine to add your own tool or project — many valuable resources come from practitioners who built something they needed. Just make sure it genuinely belongs alongside the existing resources and isn't just a placeholder.

## Response Time

PRs are reviewed quarterly (roughly January, April, July, October). We batch reviews to avoid churn. If something is clearly broken (dead link, factual error), we'll merge a fix sooner.
